## Technical Debt log

Document items that should be addressed later to prevent drift or fragility.

### Debt template

| Item | Date identified | Impact | Risk | Priority | Recommended remediation |
| --- | --- | --- | --- | --- | --- |
| Example debt | YYYY-MM-DD | Description of impact | Risk level | High / Medium / Low | Proposed fix |

### Common technical debt categories

- Unclear ownership of modules or responsibilities
- Hardcoded configuration values
- Weak validation or missing input contracts
- Excessive coupling between layers
- Missing tests for critical scenarios
- Incomplete or outdated documentation
- Unclear dependency failure handling
- Deferred refactoring for stability or performance

This memory file should be kept current at the end of each working cycle. Update it whenever:
